Manage Redesign

Three of the four Manage tabs need work, and they need different amounts of it. Punctuality is a full redesign — it was never covered by a handoff and it's the last hand-rolled manager table in the app. Manage Time keeps its single scroll but gets ordered by urgency. Coverage needs chrome and a date control, nothing more. Admin is already restructured; it isn't touched here.

The cross-cutting fix comes first: Metrics, Coverage and Punctuality currently have three different date-range controls. One of them is already right.

01 — Shared date-range control

Metrics already solved this. Adopt it.

The 18pre Metrics round built pressed-state preset chips with aria-pressed and a shared Custom… disclosure, and retired .m-preset-chip. Punctuality has presets with no pressed state — the exact defect that round fixed. Coverage has no presets at all, just two date inputs and a Load button. Extract the Metrics control as mtDateRange_ and have all three call it.

One thing must stay different: Coverage looks forward and Punctuality looks back. Same component, different preset set — not the same presets.

02 — Punctuality

A number you can act on

This serves two jobs equally — spotting who needs a conversation, and keeping a complete attendance record — so the design does both rather than picking. Outliers get named at the top; the full roster stays below, sorted least-punctual-first as an actual sort rather than a sentence claiming it.

The substantive addition is the expanded row. Today a manager sees "avg late 18m, worst 41m" and cannot see which days — so the number can't survive a conversation with the rep. mtRenderTable_ has had an optional detailRow(r) hook since cycle 14, unused. This is what it's for.

Was
Bare view-title h1 · hand-rolled .punct-table · presets with no pressed state · no sort · no drill-down.
Now
Shared .app-bar · mtRenderTable_ with sortable + sticky headers · mtDateRange_ · expandable per-rep detail.
Cleanup
Three dead local functions (isoLocal ×2, iso in punctPreset_) — leftovers from the L-5 timezone fix, defined and never called.

03 — Manage Time

Same scroll, ordered by urgency

Ten-plus cards in source order, mixing things that block a person today (a pending PTO request, a missed clock-out) with things done monthly (ADP export, sheet doctor, PTO reconciliation, the audit log). Nothing is removed and nothing moves to another tab — the order changes, and the chores collapse.

The rule that makes collapsing safe: a collapsed panel still shows its state in the summary row — a count, a status dot, or "nothing to do". Collapse that hides a problem is worse than a long scroll.

One chrome change too. This tab already has an .app-bar, but it still reads Time Clock › Manager Dashboard — stale since this view moved into the consolidated Manage tool. The crumb becomes Tools › Manage › Manage Time and the H1 matches its tab label in the registry.

05 — Implementation notes

What this costs to build

Free — client only
  • Coverage + Punctuality swap .view-title-row for .app-bar. Manage Time in the same file already shows the pattern.
  • Punctuality's table moves onto mtRenderTable_ — sortable headers, sticky header, hover, tabular numerals, all free. Delete .punct-table and .punct-card.
  • Default sort = on-time ascending, replacing the "Least punctual first" prose claim with a real sort a manager can change.
  • Tri-tone thresholds: reuse mPctClass_(pct, thr)'s mechanism but pass Punctuality's own 90/75 — not Metrics' 80/50. Same function, different thresholds.
  • Manage Time reorder is markup order + disclosures. No handler changes.
  • Delete the three dead locals: isoLocal in enterCoverageView and enterPunctualityView, iso in punctPreset_.
  • Keep every guard as-is: _punctSeq / _covSeq same-view races, the D5 midnight re-anchor, isoDateTz(empTz()) roster-tz anchoring, errorStateHtml_ vs the quiet empty state.
Server work
  • getPunctualityReport gains a per-rep days[]: date, scheduled start, actual clock-in, minutes late, and a state of ontime|late|off|holiday. Everything the expanded row draws comes from that one array.
  • Include a prevOnTimePct for the "+3 pts" delta and the four weekly buckets for the trend.
  • Time off and holidays must be marked, not omitted — an absent day rendered as a gap reads as an untracked absence. Holidays come from the same source the Coverage grid uses.
  • The payload is per-rep per-day for the whole range, so cap the range server-side and keep the response bounded the way the CN tail does.
Coaching hand-off
"Log coaching" routes enterTool('develop','coaching') with a COACH_PREFILL carrying empId and a pre-written narrative ("59% on-time over 30 days; 9 late days, worst 41m on 12 Aug"). Reuses the existing Call Notes prefill mechanism exactly — and note the tool key is develop, not training; that mistake made the Call Notes deep-link a silent no-op for two cycles.
Where the mock's table chrome deviates
The Punctuality table is hand-drawn as a CSS grid because a Design Component can't call mtRenderTable_. Header and row treatment are matched to the real .m-table rules — no header fill, border-bottom:2px solid var(--line) on th, mono-uppercase at .04em, 6/8px padding, .m-num right-aligned, .m-name at weight 500. Not literal: the expanded row is drawn inline, but in the component it is detailRow(r) emitting a full-width <tr><td colspan>; tr:hover td { background: var(--paper-2) } can't show in a static mock but stays; and .m-table-wrap owns the sticky header and max-height:62vh — use the real wrapper, not the mock's rounded card.
