Coaching Redesign

Coaching is the one Training-module surface the earlier redesign bundle skipped. It still opens on a blank composer, uses a bespoke title row and toggle, and renders a flat chronological list with no way to filter it. This board brings it onto the Console token system and reorganises it around the question a manager actually opens it to answer: who needs a 1-on-1, and how urgently.

Target · train/script_coaching.html Existing tokens only 3 new server fields
01 — Manager · Team Coaching

Lead with the roster, not with a blank form

The composer moves into a drawer behind one primary button. What takes its place is a per-rep board: severity mix over 30 days, last-coached date, and a derived signal tier — so "who needs more 1-on-1 training and how urgently" is answered above the fold instead of buried under a numbers table.

Was
Composer expanded on entry · bare view-title h1 · bespoke .coach-modes pill · 4 generic KPIs · flat unfiltered list.
Now
Shared .app-bar + .toolbar-tabs · drawer composer · trend-bearing KPIs · rep signal board · filter bar with counts.
Recovered
Two things the code already stores but never showed: the linked call note (noteId) and the void reason (CO.VOID_REASON).

03 — Composer

A drawer, with kind split from severity

Praise leaves the severity ramp: kind is a two-way segmented control, and severity — now a three-step colour-coded chip scale rather than a dropdown of sentences — only appears for coaching. The stored severity enum is unchanged, so the server contract holds; the axis is split in the UI only. A Call Notes "Coach on this" prefill arrives as a removable chip, so the rep can see the link is there before saving.

04 — Critical notification email

A notice, not the content

Logging a Critical item mails the rep directly — the one severity that shouldn't wait for them to open the tool. It carries no narrative, no patient, and no TRX: the whole point of the in-app posture is that PHI-adjacent detail lives behind authentication, and an inbox is not behind authentication. So the email says that something critical was logged, by whom, and that it needs acknowledging — then sends them to the app.

Only Critical mails. Minor and Moderate rely on the in-app badge and the existing accountability digest, which is what keeps this email meaningful when it does arrive.

Trigger & build notes
When it sends
  • Inside createCoaching, only when severity === 'critical', to the rep's roster address, cc the logging manager.
  • After the row is committed and outside the ScriptLock — mail inside the lock is the M-7 all-hands-assign problem.
  • A send failure must not fail the create: catch, log, and return success with a mailed:false flag so the toast can say "logged — email didn't send".
  • Reuse the Nudge path for re-sends rather than mailing again on edit; stamp NudgedAt so it rate-limits.
  • Voiding a critical item sends a short retraction to the same recipients — an unretracted "critical" notice is worse than no notice.
Content contract
  • Never include whatHappened, whatShould, patientTRX, or the linked note id. The subject line names no severity and no patient either — it's read on lock screens.
  • Manager name, timestamp, severity, the ack requirement and the deep link are the whole payload.
  • The audit log records that mail was sent (coachId only) — content-free, same as every other Coaching audit row.
No new email chrome — call the shared shell
The 2026-08-13 email-alignment audit put 19 of the app's 30 send sites on buildBrandedEmailHtml_ + brandedKvRows_. Everything above is that shell, unmodified — this email adds a caller, not a template.
buildBrandedEmailHtml_({
  subLabel: 'Training · Coaching',
  heading: '… logged a critical coaching item for you',
  tone: 'danger',
  statusLabel: 'Needs your acknowledgement',
  rows: brandedKvRows_([…]),
  ctaUrl: safeWebAppUrl_('develop'),
  ctaLabel: 'Open Coaching'
})
  • tone:'danger' already exists — the CN urgent digest and clientErrSpikeAlert_ both use it. The 3px rule under the heading is the shell's tone rule, not a new red rail.
  • Mark sits on the card over a navy rule, never on a navy fill — logoUrl is a transparency-free JPEG.
  • subLabel is the module eyebrow every branded caller passes ('Call Notes' on the digests). Coaching's is 'Training · Coaching'.
  • The CTA goes through safeWebAppUrl_('develop') — returns '' and the wrapper drops the button rather than shipping a dead one. Don't hand-build the URL.
  • Verify the shell's exact slot order against Code.js before building — the mock reconstructs it from the restyle record, not from the source (the file is past the size a read can reach).
  • Eyebrow type: the mock sets subLabel in bold Arial caps at .14em, not Courier. Email can't load Inter Tight or JetBrains Mono, so the in-app mono kicker falls back to Courier New — which is why it reads as a leftover rather than a decision. Arial keeps the whole email in one family. This is a shell-level change — it applies to every branded caller, and to intakeEmailShell_'s matching label. The mono footer is untouched.

06 — Implementation notes

What this costs to build

Free — CSS and render-string only
  • .app-bar + .display-title replace the bare .view-title row
  • .toolbar-tabs replaces .coach-modes — delete the bespoke rules
  • Composer moves into a drawer behind the primary button (markup order only)
  • Severity chips replace the <select>; the enum is unchanged
  • Card hierarchy: coaching point in a tinted, accent-ruled block
  • Overdue moves from a full red row tint to inset 3px 0 0 var(--destructive)
  • Filters, search, month grouping — all client-side over the cached COACH_STATE
  • Rep signal board derives entirely from analytics.perRep, already returned
  • Call-note link uses the stored noteId via enterTool('callnotes', …)
Server work — 3 fields
  • RepResponse — optional reply captured on acknowledgeCoaching. 2000-char cap, HR store only, audit stays content-free.
  • FollowUpAt — the "revisit on" date; feeds a Revisit due filter and the accountability digest.
  • NudgedAt — last reminder sent, so Nudge can rate-limit to once a day.
  • All three self-heal the header row the way VoidReason did (COACH_HEADERS 14 → 17).
Signal tier — derived, not stored
Weighted 30-day score: critical 4 · moderate 2 · minor 1 · praise −1, plus 2 per overdue item. Priority ≥ 6 or any critical · Watch 3–5 · Steady 1–2 · Clear ≤ 0 · No signal when nothing logged in 21 days. Board sorts by score descending so the reps needing a 1-on-1 sit at the top.
