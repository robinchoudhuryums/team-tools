Admin Redesign

System health outgrew the container it was put in. It's now three status cards plus automation health, storage health, client errors, deploy readiness and the queue inventory — more content than the Tags or Compliance sub-tabs — folded into an unlabelled disclosure at the bottom of Overview. It gets promoted to its own System tab.

The second change is hierarchy. Today a passing check costs a full row, so a healthy system renders six green sentences and an unhealthy one hides the real warning among them. Problems get room; all-clears collapse to a count.

Target · cn/script_callnotes.html No new RPCs Queue inventory kept
01 — Overview

Cards that go somewhere

The three status cards stay on Overview, because a health glance belongs on the landing pane. What changes is that they become links — the obvious gesture on a warning card is "show me why", and today that means scrolling past the KPI strip and usage panel to find a generic disclosure. Now each card opens its own section of the System tab.

Deploy readiness moves down and folds to a summary line. You've deployed, so a permanent "All clear" checklist no longer earns the top of the page — but it stays one click away for the next release.

Order today
Deploy readiness → status cards → KPIs → usage → System details disclosure. Chronological by when each was added, not by what's looked at.
Proposed
Status cards → KPIs → usage → deploy readiness (folded). Health detail moves out entirely, to its own tab.
Rename
Call Notes · Admin → Admin under Manage. The subtitle names what the page actually governs.

02 — The System tab

Problems first, all-clears counted

Everything that was behind the disclosure lands here, reordered by whether it needs you. Needs attention comes first — each problem stated once, with the fix and the link to where the fix happens. Then a single line accounting for every passing check, expandable. Then the reference material: the storage inventory, the queue inventory, the client-error tail.

The fixes are already written in the code — cnRenderHealthPanel_ tells you which alias row to add, cnRenderStoragePanel_ names the exact File → Settings path. They're just buried three levels down. Promoting them is most of the work.

04 — Implementation notes

What this costs to build

Free — client only, no new RPCs
  • Add tab('system','System') and a sixth .cn-admin-pane. Move #cn-admin-health and #cn-admin-storage into it; delete the disclosure and cnToggleSysDetails_.
  • Move #cn-admin-deploy below the usage panel and wrap it in the same disclosure pattern.
  • cnViewTitleBar_ → the shared .app-bar: breadcrumb Tools › Manage › Admin, title Admin, new subtitle.
  • cnSetSysCard_ gains an onclick → cnAdminTab_('system') plus a scroll to its section, and a chevron affordance.
  • Storage rows → mtRenderTable_. Retire .cn-storage-row / -main / -role / -meta.
  • The tab badge count is problems.length from the payloads already fetched.
The one real refactor
cnRenderHealthPanel_ currently decides tone and emits markup in one pass, interleaved in payload order. Split it: one pure cnHealthFindings_(health, storage) returning a flat array of { id, area, severity, title, detail, fix, link }, then render severity !== 'ok' into Needs attention and count the rest.
  • It's pure, so it's Node-pinnable like qaPeaks_ and the other pinned helpers — worth a test asserting every findings id appears in exactly one of the two buckets.
  • cnSetSysFromHealth_ then derives the three cards from the same array instead of re-deriving tone independently. That removes the current risk of a card disagreeing with the panel under it.
  • Keep the CDR card toning off likelyMismatches, never raw unmatchedAgents — the existing comment explains why a card that can never go green trains the reader to ignore it. That reasoning is right and should survive the refactor.
Do not break these
Every panel keeps its contained failure — the C17 batch-2 fix exists because errorStateHtml_ into area destroyed all five panes and the slots six in-flight loaders were targeting. A sixth pane means a sixth slot to keep intact. Keep the currentView !== 'callNotesAdmin' guard on every handler, and the failed ≠ absent rule (E7/F16) — a retention or health panel that can't load must say so, never render blank. Keep the M-8 fix: the enter path must perform the same empty-pane load the click path does, or a manager returning to a persisted adminTab lands on an active tab over an empty pane. That bug applies directly to the new System tab — persist it in CN_STATE.adminTab and handle the re-enter. Keep esc() on every server string.
Smaller things in the same pass
  • Redundant fallbacks on defined tokens: var(--warning-deep,var(--warn)) and var(--success-deep,var(--accent)) in cnRenderDeployReadinessHtml_ and cnRenderStoragePanel_ — same family as the --accent-deep fix in the earlier handoff.
  • The disclosure button needs aria-controls alongside its aria-expanded — and the new deploy-readiness fold inherits that requirement.
  • cnQueueInventoryHtml_ stays visible (your call), but give it the heading its comment already implies — the question it answers, not "Queue inventory · discovery". A reader should know why it's on screen.
  • Six sub-tabs will overflow a phone. .toolbar-tabs must scroll inside itself rather than push the page sideways — the V-6 390px fix.
  • Sort the storage table with the problem rows first, so a tz drift or unreachable store doesn't hide at row 8 of 9.
