QA Redesign

The QA module is carefully built — seq guards on every async path, the waveform strictly decoration so no failure touches playback, shared builders so the reviewer and agent surfaces can't drift. The findings here are about what the screens are organised around, not how they're coded.

And that's the whole of it. QA is used for periodic audits of a few sampled calls per employee, scored and compared to find who needs coaching. But the queue is built as a flat list of files — it answers "what recordings exist," when the real question is "which employees have we covered this quarter, and who still needs sampling." Same shape as the Coaching and Punctuality findings: the data was per-item when the job was per-person.

01 — Recordings · audit coverage

Lead with who's been sampled

An audit period becomes the frame for the whole tab, and the first thing on screen is per-employee coverage: sampled against target, average this period, movement since last, and whether they're done, short, unstarted, or exempt. Sorted so the people still needing calls pulled sit at the top.

The file list doesn't go away — it moves below, as section 02. It's still the working surface once you know whose calls you're pulling.

The gap
Nothing in the module knows about an audit period or a per-employee target. A reviewer can't tell whether this quarter is finished without counting cards by hand.
Already half-built
qaSampleRecordings already assigns least-reviewed-agents-first. That's coverage-fair sampling with no coverage display to justify it.
Exemption
"Consistently high scorers can be exempted" has no representation at all today. It needs to be visible, earned, and expiring — see §1c.

02 — The recordings list

Six uniform fields want a table

You left the shape to me, so: a sortable table, matching the Stats tab in this same module — which already proves mtRenderTable_ works here. Cards cost three times the vertical space per row and can't be sorted, and for audit work the scan is "which of these is long, unassigned, and belongs to someone I still owe calls for."

Filter chips gain counts. Duration arrives as a real column with short/medium/long filtering. Skipped becomes reachable — it's in the schema, styled in CSS, and no button in the app can set it or filter to it.

What the table adds
  • Length replaces file size. Size is bitrate-dependent — a 4 MB file could be 3 minutes or 30.
  • Agent is promoted to a column, since it's what audit work sorts by. Unattributed is called out, not blank — it's silently excluded from Stats.
  • Skipped reachable: a Skip action in the detail, a filter chip, and a reason line. Currently a dead status.
  • Sort defaults to newest dropped; every header sorts.
  • Done rows carry their score so you don't open a finished review to see how it went.
Assign… is a picker, not a prompt
Today it's uiPrompt with a typed email, the valid members comma-joined into the message text, and a validator that rejects anything else. The set is known, small, and already validated — make it a list of members with review counts, so routing work also shows who's loaded.
03 — Recording detail

The player should never leave the screen

Today it's one column: head, agent row, player, scorecard, comments. But reviewing is listening and annotating at the same time, and the transport scrolls away the moment you read a comment or reach for a rating. Two panes at wide widths, player pinned on the left; scorecard and comments scroll on the right.

Agent attribution moves out of its bare label-and-input row into the player pane, where it reads as part of identifying the call rather than an afterthought — and it warns when a typed name isn't on the roster, because Stats groups by that string and a typo silently forks a new row.

04 — The comment anchor

Pause, pin, resume

Today qaSubmitComment_ reads audio.currentTime at submit. Hear something at 12:04, type for twenty seconds, and the comment files at 12:24 — pointing at whatever came next. The live-updating button label makes it look deliberate, which is what makes it hard to notice.

You picked pause and pin. The first keystroke does both: playback pauses, the moment is captured as an editable chip, and posting resumes from where you stopped. Post & stay paused exists because a bad stretch of call usually earns two comments in a row.

05 — My Reviews

Read-only, but a real player

You chose to keep this read-only, so there's no acknowledge and no reply here — the scope option I offered bundled those with the player work, and the specific answer wins. Coaching remains where a response is recorded.

What changes is parity. An agent listening to their own call currently gets a bare <audio> element — no speed, no ±5s, no keyboard. Reviewers got all three because reviewing is hard listening; hearing your own 30-minute call is the same work. qaDrawWaveOn_ was already extracted to share exactly this kind of chrome — the transport should follow it.

06 — Implementation notes

What this costs to build

Free — client only
  • All three views swap .view-title-row for .app-bar; the QA · title prefix goes with it.
  • Queue list → mtRenderTable_, which the Stats tab in this file already uses. Retire .qa-card, .qa-card-*.
  • Filter counts derive from the cached QA_STATE.queue.recordings — no new call.
  • Search + length filter are client-side over the same array.
  • Two-pane detail is a grid + position:sticky; single column below 1000px.
  • Pause-and-pin: a pinnedAtSec in QA_STATE, set on first input, cleared on post/discard. qaSubmitComment_ sends it instead of live currentTime.
  • Skip = qaSetRecordingStatus(id,'skipped'). The endpoint and the CSS already exist; only the button and chip are missing.
  • My Reviews transport: extract qaRenderTransport_ to take an audio element, the way qaDrawWaveOn_ was extracted.
  • Scale anchors + running average are label text over existing state.
Server work — 4 fields
  • DurationSec on the recordings index — captured at sync if Drive exposes it, else written back on first successful decode. Feeds the column and the length filter.
  • AuditPeriod — the period a recording is counted in, so re-sampling an old call doesn't credit the current quarter.
  • ExemptPeriods — per-employee exemption grants with the period they expire in.
  • SkipReason — pairs with the now-reachable skipped status, the way VoidReason pairs with a voided coaching item.
  • getQaQueue gains a coverage block: per-employee sampled/target/avg/prev-avg/last-reviewed/exempt. All derivable from data already in the QA spreadsheet plus the roster.
Coaching link
Log coaching routes enterTool('develop','coaching') with a COACH_PREFILL carrying the agent and the timestamped comments as narrative. Store a reviewId on the coaching record, mirroring noteId — and render it, which is the mistake the Coaching handoff documents. Tool key is develop, not qa or training.
Do not break these
Every audioSeq / myRevAudioSeq / seq / statsSeq / myRevSeq guard (INV-156) stays, including the if (QA_STATE.det) return in the queue refresh. The waveform stays decoration — size gate, undecodable format, and any throw must all leave playback untouched, and decodeAudioData keeps getting a buffer copy since it detaches its input. Keep .qa-wave[hidden] — display:block otherwise beats the UA's [hidden] rule. Keep the agent player off qaGetAudioChunk and on the scoped getMyQaReviewAudioChunk, and keep failures there Drive-link-free. Keep esc() on every server string and the typing guard in the keyboard handler.
Smaller things worth fixing in the same pass
  • .qa-kbd-hint uses --muted-3, the below-AA decoration token, for instructional text. Move to --muted-2. (Its use in qaDrawWaveOn_ for unplayed bars is correct — that is decoration.)
  • qaSetRating_ re-renders the whole form per click, rebuilding the notes textarea. Notes survive, but the caret doesn't — toggle the row's aria-pressed in place instead.
  • No unsaved-work guard: a filled scorecard and a typed comment vanish on Queue. Reuse the trainLoadMgr_ dirty-form pattern in qaBackToQueue_.
  • The keyboard hint appears twice — in the transport and again in the comments note.
  • .qa-btn / .qa-chip / .qa-status / .qa-empty duplicate the shared button, .toolbar-tabs, .kicker-pill[data-tone] and .no-data vocabularies. The module already reuses mtRenderTable_, errorStateHtml_, icon, showToast, uiConfirm — finish the adoption.
