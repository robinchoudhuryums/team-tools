---BROAD SCAN IMPLEMENTATION SUMMARY---
Findings implemented:
- TC2-1 — the reminder ticker in a long-lived window kept yesterday's half-day, PTO, schedule and punch state, so on the next day it nagged a rep on a day off or stayed silent on a working day. It now uses a state snapshot only for the day it describes, and forces a refresh at the rollover.
- TC2-6 — onboarding accepted a misspelled timezone id ("America/Chicgo") that passed the shape check, which the runtime then silently read as GMT. An Intl probe now refuses an id the runtime does not know.
- TC2-3 — the coverage planner treated an approved half day as a full day off. It now counts the rep as a tentative presence across the shift ("Half day — works part of the shift"); a morning plus an afternoon half is still a full day off.
- TC2-4 — a column-O shift override kept the timezone-default breaks, so a 1 pm–9 pm rep was reminded of, and graded against, a 12:00 lunch. An override with no per-employee break list now keeps only the defaults inside its own shift; the ticker reminds of a break only inside the shift.
- TC2-7 — punctuality marked today "no clock-in" before the shift had started. Today before the start (plus grace), or a date still ahead, now reads "not started yet".
- TC2-8 — Team on-time showed 0% when no day in the range was graded, and company holidays were drawn as working days in the manager sparkline and trends and as understaffed days in the planner. No graded day now reads "—"; holidays leave the trends and are closed in the planner.
- COA-2 — the client's `coachTsMs_` read coaching stamps as UTC, shifting the 30-day and quarter windows (and relative days) by 5.5 hours. It now reads them in CONFIG.TIMEZONE, as the server has since cycle 22 D1.
- MET2-2 — the inbound-volume average counted a company holiday's handful of calls as a working weekday in its denominator. Holidays are now left out.

REGRESSION RISKS:
- A window whose state refresh keeps failing after a rollover fires no break / clock-out / clock-in reminders that day (it retries every 10 minutes). Chosen: a stale day's reminders are wrong reminders; the daily missed-punch email stays the backstop.
- An onboarding with a valid but runtime-unknown zone id would be refused (Apps Script's ICU knows every current IANA id; deprecated aliases may differ). The message names the spelling; a UTC/GMT offset token is not probed.
- A rep with a column-O override and no per-employee breaks loses reminders and lunch grading for tz-default breaks outside their own shift (the point of the fix); one inside it is kept.
- The manager trends now show a holiday-free run of workdays, so a bar's date can jump over a holiday; the coverage planner draws a holiday as closed.
- Coaching windows and relative days move by the storage zone's offset (5.5 h for Asia/Kolkata) — they become correct, which can change a borderline count on deploy.
