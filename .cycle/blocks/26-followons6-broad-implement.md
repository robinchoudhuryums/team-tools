CHANGES:
FT1 — held text | web-app/cn/script_callnotes.html | When the "Recovered text" page cannot be made — the server refuses (the pad has the most pages it holds) or the call fails — `cnScratchHold_` moves the text in `pending` to a `held~…` key, which no page id can equal. `cnScratchNextPage_` never returns a held key, so no save sends it; `dirty` counts pages only; the browser mirror keeps it across a reload; the pad never opens on it and never reads it from the server as a page. After a hold of the page on screen the pad re-opens that page from the server, so the unsaved text is no longer shown as if it were the page.
FT1 — the race, one add | web-app/cn/script_callnotes.html | `cnScratchRecover_` marks the text unsendable before it asks for the new page (a keystroke in that second armed a save onto the changed page), and runs one add per text (`recovering`). `cnScratchPageOp_` takes an optional failure callback.
FT1 — the row | web-app/cn/script_callnotes.html, web-app/script_core.html, web-app/styles.html | A row above the pad's toolbar (`#cn-scratch-held`) says what is kept (a plain-text preview) and, with a full pad, that a page must be deleted; **Move to a new page**, **Copy it** (the outcome reported; a blocked copy opens the copy dialog in the layer above the floating pad — `manualCopyModal_`'s new `above` option) and **Discard** (a destructive-tone confirm; removed from the browser at once). The row is rewritten only when it changed. Held text gets its page without being asked after a page is deleted and at the next open — never against a pad known to be full; a quiet retry that fails says nothing, the rep's own Move is answered with the server's reason. With the pad closed, a hold is said in a sticky notice that opens the pad.

A clean modal, and a pick of the day already shown, ask nothing.
FT3 | web-app/script_tour.html | `TOUR_VIEW_LOADERS` = `renderLoading`'s full-view loader AND the inline `.m-loading`, each scoped to `#view-area` and read visible-only. Skeleton blocks are deliberately not a signal.
