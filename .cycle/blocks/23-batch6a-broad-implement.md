---BROAD SCAN IMPLEMENTATION SUMMARY---
Findings implemented:
- TC-03 — a single-date time-off request on a company holiday (or a weekend) was accepted and, once approved, deducted; only the range path skipped closed days. Both single-date paths (rep and manager, auto-approve included) now refuse a closed day by name before anything is written.
- TC-04 — the Approved↔other balance transitions assumed a deduction had happened because the row was Approved, so a request approved while tracking was off, or while the rep's PtoEnabled was FALSE, credited a day back when it was later denied. An approval now records what it took on the row, and un-approving restores exactly that.
- TC-05 — a rep's adjustment had no clock-order check, so an AM/PM slip (in 08:00, out 05:00) was paid as a 21-hour overnight shift. Apply now, submit and approval refuse an equal pair or a shift longer than 16 h; a real overnight shift is allowed (the wrap is deliberate, g127).
- TC-06 — `fixPtoReconciliation` with tracking off credited nothing yet marked the rows Reconciled and audited `creditedAnnual=N`. It now refuses up front when no credit can land, treats a credit that wrote nothing as a failure (rows reverted), and the detector and the fix both count what each approval actually took.
- TC-08 — the sheet doctor's duplicate collapse kept the last row APPENDED, so it could delete the lunch return a break was paired with and keep a stray. It now keeps the stamp the hours already count, so a collapse never changes pay; the card names the kept stamp.
- CORE-07 — the `EmployeeOffboard` audit row named the admin as its subject and put the offboarded id in PunchDate. It now names the person offboarded, PunchDate blank, the admin as actor.
- VIS-1 — the Day Edit hint said "Set each punch's time in 24-hour format" above native time inputs that render AM/PM. It now says "(check AM or PM)".
