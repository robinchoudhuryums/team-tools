CHANGES:
I1 | intake/script_intake.html, run.js, runDom.js | The cross-language path re-parked the prefill and went through `intakeSetLang_`, which snapshots the form before re-entering and restores it after — i.e. AFTER the amendment applied — so the form held the rep's current draft (another patient) or blanks while `amendOf` stayed set, and the send went out "AMENDED" for patient A. The consume now flips the language and re-enters directly (`intakeReenterForm_`). A second hole in BOTH languages: the enter restored the stored draft first, so every answer the original left blank kept the draft's value; a parked amendment now skips the draft restore (`intakeAmendPending_`) — the amendment IS the form. Pinned in jsdom for ES and EN (patient, a present answer, an absent answer, amendOf, banner, consumed once) plus an ordinary user flip that still carries typed answers; the existing order pin now also requires the draft-skip in both enters and no `intakeSetLang_` in the consume.
C4 | cn/script_callnotes.html, run.js, runDom.js | The Save & Compose transaction carries an `owner` ('dept' by default). A tab switch MOVES it (owner 'ext' / back to 'dept') instead of setting it to null; each composer's close rolls back only a flow it owns (`cnRollbackComposeFlow_`, extracted from the department close); the external send COMPLETES it (`cnCompleteComposeFlow_` — form, timer and sticky draft cleared) before its own close. Before, nothing ever cleared the form after an external send, the re-entry guard was off while the external composer was open, and the next Save wrote a duplicate note with the untouched fields carried into the next patient's note. External cancel after a switch now rolls the save back, the same as a department cancel (previously the note stayed saved with its text still in the form — the duplicate's other door). Pinned in jsdom both ways; CMP-4's dirty-toast guard updated to the owner check.
K6 | kb/script_kb.html, runDom.js | `kbDrawerRenderHome_(opts)`: with the lookups mounted and no `fresh`, it patches only `#kbd-home-blocks` (bookmarks / recents / hint) plus guidance and suggestions; the drawer OPEN passes `fresh:true` (the next caller). The tree response used to rebuild `#kbd-body` and wipe a payor, item or address typed mid-call. The shot `reference-drawer-xref-light-wide` now shows its typed inputs above its results (it showed empty inputs over full results).
K2 | kb/script_kb.html, runDom.js | A fresh build of either host (`kbLookupsForget_` — the drawer open and the landing band's first render) clears that host's `KB_OOP.last` / `KB_INS.last`, and every lookup response (price, eligibility, the degraded fallback, payor) is dropped unless the results host it was requested for is still in the document (`kbLookupHostLive_`). Before, the next payor lookup's cross-reference repaint drew the previous caller's item and delivery verdicts under two empty inputs, and a late response could paint into the next caller's panel. Pinned in jsdom (same node, value, focus, blocks refreshed; a fresh open forgets both caches and a late payor answer paints nothing).
C3 | cn/script_callnotes.html, run.js, runDom.js | History notes carry the range they were loaded for (`historyNotesKey`) and render only under that range's label; a failed refresh of the SAME range still keeps last-good (C17-5), a failed load of a DIFFERENT range shows the failure. A span over the server's cap is refused before the RPC with the reason (`CN_HISTORY_MAX_SPAN_DAYS`, same arithmetic as `getMyCallNotesRange`; a Node pin reads the server literal). Pinned in jsdom (new range fails, same range fails, over-cap refused with no RPC).
D6 | train/script_empdocs.html, runDom.js | The Create-a-document form is built once per enter and patched around (`edIssueFormLive_`): the employee and template pickers re-sync their options in place keeping the selection (`edSyncSelect_`; a deleted template falls back to scratch), `#ed-mgr-rest` (templates + documents) is re-rendered, and a failed refresh or a dashboard `{error}` lands beside the form. A successful issue or draft save sets `mgrFresh`, the one action that resets it. Before, save/delete template, release and void each rebuilt the page and wiped the half-written document. Pinned in jsdom, the reset driven through the real `edSubmitIssue_` after a NO BITE on a first draft that set the flag by hand (g138).
D7 | train/script_coaching.html, runDom.js | `COACH_STATE.replyDrafts[coachId]` is fed by the delegated input listener and rendered (escaped) into each card's reply box; a focused reply box keeps focus and caret across `coachRenderMy_`; the draft is dropped when its acknowledgement lands. Before, a filter chip, the search box or the reload after acknowledging ANOTHER item rebuilt the box empty. Pinned in jsdom (re-render, the other-item reload, drop on send, an escaping round trip).
C6 | cn/script_callnotes.html, run.js, runDom.js | `CN_SCRATCH.latest` holds the text last typed. Close clears the debounce, captures the field and flushes; a save that has to wait (one in flight) drains from `latest` after the modal is gone; a success marks the pad clean ONLY if nothing newer was typed; a failure with the modal gone is a toast; the next open carries the unsaved text (instead of the server copy) and retries. Before, a close during an in-flight save queued a drain that found no field and saved nothing, and a success marked newer typing clean. R3 #5's flush-on-close shape updated. Pinned in jsdom end to end.
C10 | cn/script_callnotes.html, runDom.js | Each confirmed submit stamps a monotonic `_confirmSeq` (a client-transient key the render signature ignores); `cnRefreshRollingStack_` keeps any confirmed note newer than its own request alongside the `_pending` ones. A counter, not a clock (a first draft used `Date.now()`, which could tie within a millisecond). A later poll stays authoritative. Pinned in jsdom both ways.
C11 | cn/script_callnotes.html, runDom.js | `cnClearActiveForm_` first runs `cnVoiceStopAll_`: every running session's handlers are detached, THEN it is aborted (abort still fires onend), and the mic resets. Every clear path — submit, Clear, a completed Save & Compose — goes through it. Pinned in jsdom with a stubbed engine delivering a late result.
