CHANGES:
K3 | 70_kb.js, run.js | The OPEN branch reads its parenthetical: "except/excluding/not/no/only/but/without/outside/other than…" makes the value unknown ("no restrictions" is stripped first, so it stays open). The distance clause (`oopRadiusClause_`) removes the distance, the warehouse names with their own state code, and a fixed set of connective words; any token left over is a restriction this grammar cannot evaluate, so the clause is unknown. Before, only an uppercase state code left over was noticed. Unknown never lifts out of pocket, so the refusal carries through both verdicts. The operator's live phrasings (including "100 miles from our Dallas location" and upper-case cells) still parse; the distance is now removed by POSITION, where it used to be replaced by its lower-cased text, which missed "MILES".
K1 | 70_kb.js, run.js | Every "N miles" is found; each clause runs from its distance to the next (the first also takes any prefix, so "TX, 100 miles of Dallas" still trips F-23). Clauses with the same distance merge into one radius, so the operator's live "100 miles of Dallas warehouse, 100 miles of San Antonio warehouse" parses exactly as before; different distances become a union, and the union's yes names "any one of the listed distances" rather than a city list. A registry name before the first of two distances cannot be assigned, so the value is unknown; one unreadable clause makes the whole value unknown, with the delivery table blamed when that is the cause. A trailing city clause joins the union flat.

The loader keeps a row whose State cannot be read but flags it (and names it in the diagnostics); it never matches, and `locCityUnreadable_` hands it to the check, which answers "cannot tell" and names the cell.
