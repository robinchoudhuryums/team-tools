Honest impact summary
- What changed for a user right now: almost nothing, and that is the honest read. Two of the four batches ship no `web-app/` code at all (C entirely; P's process half), and the two that do are a guard that refuses a save nobody on this deployment is yet large enough to make (Q) and a suite reorganization run from the editor (S). The only user-visible additions are the byte-budget line on twelve Admin editors and a third capability line on Admin → System. A rep sees no difference.
- What changed for the next developer in this subsystem: numbers in CLAUDE.md are no longer claims — CI refuses a merge where the document and the tree disagree, and a second copy of a total in prose is itself banned. A suite run now explains its own environment (`_suiteEnvCheck_`) and prints its own expected count, so the next surprising run starts from data rather than a hypothesis — the last three surprising runs (302/312 on a narrowed `ADMIN_EMAILS`; the two-overlapping-executions run; 315 vs 312) were all deployment state rather than code, each costing a diagnosis cycle. And `propSetBounded_` is the one writer for every JSON-blob property, so the refuse-vs-degrade decision is made once instead of per endpoint.
- What became safer under scale / concurrent load: two things, both real and both latent. `propSetBounded_` turns an opaque platform throw AFTER a success-claiming audit row into a named refusal BEFORE anything is written. `drFindRowByReqId_` removes a per-click whole-tab read of a PHI-bearing table that grows without bound. Neither has bitten; both would have. The suite shard addresses a third: a mid-shift full run held the ONE project ScriptLock for ~18 minutes, making live punches queue behind test writes.
- Was effort spent on dead code / zero-caller paths / future-proofing? Yes, and it deserves naming rather than excusing: four batches, one production fix, and that fix was found incidentally while writing a pin. Three of the four are infrastructure. That was the deliberate shape of the next-steps plan — the audit had already been reflected, and these were the items it deferred — but it means the set's value rests entirely on preventing future cost, which is the hardest claim to verify. The measurable evidence it was not wasted: C caught two live drifts on its first run (a Key Design Decision reading "the 43 Admin-exclusive endpoints" where the code enforces 50; 315 editor registrations where Q had made it 316), and S caught a dead test on its first pin. The measurable evidence against: P1, which bought nothing and is this set's should-have-been-deferred.
