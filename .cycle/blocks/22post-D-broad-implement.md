REGRESSION RISKS:
- Every tracked department email now sends through GmailApp (a draft, then send) instead of MailApp. Same From, name, Reply-To, CC and BCC; same daily recipient quota; the GmailApp scope was already granted (the Spanish inbox and REP_SENDER_FROM use it). A failure between createDraft and send leaves nothing behind (the draft is deleted), but a send that succeeds and then throws reading the thread returns '' — the request is then simply not scanned.
- Reply-To now carries the deployer's mailbox beside the agent, so a department's plain Reply reaches both; the agent still receives it.
- Rule 3's domain clause (operator-agreed) means any colleague on the department address's domain counts as the department — e.g. a manager replying "done" resolves. Mark unresolved is the recovery.
- A "done"-style reply that is not actually done resolves the request (the heuristic's false positive); it shows as "replied" credited to the replier, and Mark unresolved reopens it — the scan then ignores that reply.
- Requests sent before this deploy carry no thread and are never auto-resolved (stated in the flag's description).
- The hourly rider shares runHourlyJobs' six-minute execution with the EOD digest and Spanish auto-assign; the 150-thread cap bounds it.
